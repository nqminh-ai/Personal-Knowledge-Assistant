STEP-BY-STEP CÁ NHÂN — 12 TUẦN

Từng bước cụ thể cho mỗi thành viên

Chi tiết hoá bảng phân công theo tuần thành các bước làm việc cụ thể cho từng người — có công cụ, deliverable rõ ràng mỗi tuần. Dùng để mỗi thành viên tự theo dõi tiến độ cá nhân độc lập với bảng tổng.

A — Data & Ingestion

Corpus, parsing, OCR, metadata, dataset QA, word segmentation
Sứ mệnh: Biến tài liệu thô (PDF/DOCX/PPTX/scan) thành dữ liệu sạch, có cấu trúc, có provenance — nền tảng cho mọi module phía sau.

  1. Khảo sát nguồn & lập kế hoạch thu thập

    • Liệt kê toàn bộ tài liệu nhóm đang có (slide, giáo trình, notes) theo môn/chủ đề
    • Ước lượng số lượng còn thiếu so với mục tiêu corpus (đủ đa dạng layout, có phần "dirty data" thật)
    • Viết kế hoạch thu thập: nguồn bổ sung nếu thiếu, định dạng ưu tiên
    Khảo sát
    Deliverable: Data collection plan (1 trang)

  2. Thu thập & gán metadata ban đầu

    • Tập hợp tài liệu thật vào thư mục theo doc_id
    • Ghi metadata: filename, loại tài liệu, nguồn, số trang, ngày
    Pandas
    Deliverable: Corpus v0 + bảng metadata thô

  3. Build parser đa định dạng + OCR

    • Viết parser PDF (giữ page number), DOCX, PPTX (giữ slide/section)
    • Test OCR trên tài liệu ảnh scan, so sánh Tesseract vs EasyOCR trên vài mẫu
    • Ghi nhận failure mode: mất cột, sai thứ tự, mất tiêu đề
    PyMuPDFpython-docxpython-pptxTesseract/EasyOCR
    Deliverable: Ingestion script chạy được trên toàn bộ corpus v0

  4. Hoàn thiện metadata schema + cleaning

    • Chốt schema đầy đủ (doc_id, filename, type, source, page, section)
    • Viết bước cleaning: loại ký tự rác nhưng giữ nguyên thông tin có nghĩa (không xóa nhầm số liệu)
    RegexPandas
    Deliverable: Corpus sạch, có schema thống nhất

  5. Tích hợp word segmentation tiếng Việt

    • Cài và test underthesea hoặc pyvi trên mẫu văn bản đã cleaning
    • Chạy segmentation cho toàn bộ corpus, lưu bản đã segment song song bản gốc (phục vụ BM25 ở nhóm B)
    • Kiểm tra thủ công 10-15 câu xem tách từ có hợp lý không (đặc biệt thuật ngữ chuyên ngành)
    underthesea/pyvi
    Deliverable: Corpus đã segment, sẵn sàng cho B build BM25

  6. Mở rộng corpus nếu thiếu đa dạng

    • Rà soát lại corpus sau khi có early signal benchmark từ nhóm D — bổ sung ngành/loại tài liệu còn thiếu
    Bổ sung dữ liệu
    Deliverable: Corpus v1 (mở rộng)

  7. Hỗ trợ mở rộng cho evaluation set

    • Cung cấp thêm tài liệu/đoạn văn nếu nhóm D cần đa dạng hoá loại query khi build evaluation set 280-320 câu
    Hỗ trợ

  8. Hoàn thiện corpus final

    • Chốt phiên bản corpus cuối cùng dùng cho benchmark chính thức — không thay đổi sau tuần này
    • Viết datasheet mô tả corpus (nguồn, số lượng, phân bố loại tài liệu)
    Freeze
    Deliverable: Corpus final + datasheet

  9. Hỗ trợ debug khi chạy full benchmark

    • Túc trực xử lý các vấn đề liên quan dữ liệu phát sinh khi B/C chạy full benchmark (file lỗi, encoding, thiếu metadata)
    Debug

  10. Phân loại lỗi liên quan data/parsing

    • Đọc các câu trả lời sai, xác định lỗi nào bắt nguồn từ parsing/OCR (mất heading, sai bảng, OCR sai ký tự)
    • Thống kê tần suất từng loại lỗi thuộc nhóm data
    Error analysis
    Deliverable: Báo cáo lỗi nhóm data, đóng góp vào error taxonomy chung

  11. Hỗ trợ OCR mở rộng (nếu còn thời gian)

    • Nếu pipeline text đã ổn định, thử mở rộng query bằng ảnh (OCR câu hỏi input)
    Extension

  12. Rà soát cuối cùng

    • Kiểm tra lại corpus + documentation, đảm bảo README mô tả rõ cách tái tạo corpus từ nguồn thô
    Finalization
    Deliverable: Corpus documentation hoàn chỉnh trong repo

B — Retrieval Engineer

Embedding, vector store, BM25, hybrid, reranking
Sứ mệnh: Xây và benchmark toàn bộ "nấc thang" retrieval từ Dense → BM25 → Hybrid → Reranker, đảm bảo mỗi nấc có số liệu chứng minh đóng góp.

  1. Research embedding model & vector store

    • Shortlist 2-3 embedding model tiếng Việt/đa ngôn ngữ (vd bge-m3, Vietnamese-SBERT)
    • So sánh FAISS vs Qdrant, chọn phương án MVP (ưu tiên FAISS vì dễ tái lập)
    Sentence-TransformersFAISS/Qdrant
    Deliverable: Bảng so sánh ứng viên + quyết định MVP

  2. Sanity-check embedding model

    • Test similarity thủ công trên vài đoạn mẫu, kiểm tra model có phân biệt được ngữ nghĩa tiếng Việt tốt không
    • Chốt embedding model chính thức cho MVP
    Sanity check
    Deliverable: Embedding model đã chốt

  3. Setup FAISS pipeline

    • Cài đặt FAISS, test indexing với dữ liệu dummy để xác nhận pipeline chạy đúng
    FAISS
    Deliverable: FAISS pipeline test pass

  4. Implement chunking + build dense index

    • Implement 3 chiến lược chunking (256/512/1024 token, có overlap)
    • Build dense embedding index cho toàn bộ corpus với từng chunk size
    LangChain/LlamaIndex text splitters
    Deliverable: 3 bộ index tương ứng 3 chunk size

  5. Hoàn thiện Dense (S1) + build BM25 (S2)

    • Đưa Dense retrieval lên mức production-ready (query → top-k chunk ổn định)
    • Implement BM25 trên corpus đã segment từ A — kiểm tra tokenizer khớp giữa index và query
    rank_bm25/Elasticsearch
    Deliverable: S1 và S2 chạy độc lập, sẵn sàng nối generation

  6. Implement Hybrid fusion (S3)

    • Ghép Dense + BM25 bằng Reciprocal Rank Fusion (RRF)
    • Test candidate union không bị trùng lặp/lệch trọng số bất hợp lý
    RRF
    Deliverable: S3 chạy được, sẵn sàng cho benchmark early signal

  7. Implement Reranker (S4)

    • Tích hợp cross-encoder reranker (bge-reranker) sau bước fusion
    • Đo latency p50/p95 so với S3, ghi log rõ ràng để so sánh trade-off
    bge-reranker (Cross-Encoder)
    Deliverable: S4 + bảng latency

  8. Freeze cấu hình retrieval

    • Chốt embedding model, chunk size, K (candidate size) cho benchmark chính thức — không đổi sau mốc này
    • Ghi lại toàn bộ config vào file version-controlled
    Freeze
    Deliverable: Config file cố định cho S1-S4

  9. Chạy full benchmark chính thức

    • Chạy S0-S4 trên evaluation set 280-320 câu đã freeze
    • Lưu raw retrieval results (không chỉ số liệu tổng hợp) để D dùng cho bootstrap CI
    Full benchmark
    Deliverable: Raw retrieval logs cho toàn bộ 5 hệ thống

  10. Phân tích lỗi retrieval

    • Xác định câu hỏi nào bị recall thấp, sai chunk, một retriever thống trị bất hợp lý trong fusion
    • Tinh chỉnh nếu phát hiện vấn đề còn khắc phục được trong thời gian còn lại
    Error analysis
    Deliverable: Báo cáo lỗi nhóm retrieval

  11. Tối ưu nốt & ổn định hoá

    • Xử lý các vấn đề retrieval còn sót từ error analysis tuần trước
    • Đảm bảo pipeline chạy ổn định cho demo
    Stabilization

  12. Cleanup & README

    • Dọn code retrieval modules, viết README hướng dẫn tái lập (cách build index, cách chạy từng baseline)
    Finalization
    Deliverable: Retrieval module hoàn chỉnh + README

C — LLM/RAG Engineer

Prompting, context assembly, citation, abstention
Sứ mệnh: Biến evidence đã retrieve thành câu trả lời grounded, có citation đúng nguồn, và biết từ chối khi thiếu bằng chứng.

  1. Research LLM API & draft prompt v0

    • So sánh 2-3 LLM API theo tiêu chí quality/cost/latency (vd GPT-4o-mini, Gemini Flash, Qwen)
    • Viết draft system prompt v0: yêu cầu grounded generation + rule abstention cơ bản
    Research
    Deliverable: LLM API đã chọn + prompt v0

  2. Prompt template v1 + test API

    • Viết prompt template có format citation cụ thể (document/page)
    • Test gọi API thực tế, đo latency/cost cơ bản trên vài request mẫu
    OpenAI/Gemini API
    Deliverable: Prompt template v1

  3. Setup backend skeleton

    • Setup FastAPI backend, định nghĩa endpoint cơ bản (upload, query)
    • Kết nối test call LLM API qua backend, xử lý lỗi cơ bản (timeout, rate limit)
    FastAPI
    Deliverable: Backend skeleton chạy được

  4. Demo retrieval thô (chưa generation)

    • Nối API để test query → top-k chunk trả về (chưa qua LLM) — kiểm tra retrieval trước khi ghép generation
    Integration test

  5. Nối generation với Dense retrieval → S1 end-to-end

    • Ghép retrieval (từ B) + LLM generation thành pipeline hoàn chỉnh đầu tiên
    • Hoàn thiện grounded prompt: chỉ dùng context được cung cấp, có câu trả lời "không tìm thấy" khi thiếu bằng chứng
    S1 end-to-end
    Deliverable: S1 chạy được từ query đến answer + citation

  6. Hoàn thiện citation & abstention logic

    • Chuẩn hoá định dạng citation (document/chunk/page) nhất quán trong mọi câu trả lời
    • Test kỹ rule abstention với các câu hỏi cố ý không có đáp án trong corpus
    Prompt engineering
    Deliverable: Citation + abstention hoạt động ổn định trên S1-S3

  7. Multi-document context assembly

    • Cài đặt quy tắc group context theo doc_id, chèn header nguồn ([Nguồn: {filename}, trang {page}]) trước mỗi group
    • Xử lý trường hợp vượt token budget: cắt đều theo document thay vì ưu tiên 1 document
    Context engineering
    Deliverable: Context assembly xử lý đúng câu hỏi multi-document

  8. Freeze prompt & generation config

    • Chốt phiên bản prompt template và tham số generation (temperature, max token) cho benchmark chính thức
    Freeze
    Deliverable: Prompt/config version cố định

  9. Hỗ trợ debug generation trong full benchmark

    • Túc trực xử lý lỗi API (timeout, rate limit), lỗi format citation khi chạy full benchmark
    Debug

  10. Phân tích lỗi generation

    • Đọc câu trả lời sai, phân loại: hallucination, sai citation, sai đơn vị/kỳ, không tuân thủ abstention
    • Tinh chỉnh prompt nếu phát hiện pattern lỗi sửa được nhanh
    Error analysis
    Deliverable: Báo cáo lỗi nhóm generation

  11. Hoàn thiện API cho demo

    • Hoàn thiện toàn bộ endpoint, kết nối đầy đủ với frontend (từ D)
    • Đảm bảo error handling đầy đủ cho kịch bản demo trực tiếp
    Integration
    Deliverable: API sẵn sàng cho release candidate

  12. Cleanup & README

    • Dọn code generation pipeline, viết README (cách chạy, cách đổi LLM/prompt)
    Finalization
    Deliverable: Generation module hoàn chỉnh + README

D — Evaluation & Frontend

Metrics, RAGAS/NLI eval, UI, dashboards
Sứ mệnh: Đảm bảo mọi khẳng định về hệ thống đều có số liệu đứng sau, và người dùng có giao diện để thấy kết quả đó.

  1. Research metrics & draft schema evaluation set

    • Đọc RAGAS, NLI-based faithfulness scoring — hiểu cách đo groundedness
    • Draft schema: question, gold answer, gold chunk(s), query_type
    Research
    Deliverable: Schema evaluation set v0

  2. Setup annotation tool + QA seed

    • Setup Label Studio với schema đã chốt
    • Viết 30-50 câu QA seed (pilot) từ corpus đã có
    Label Studio
    Deliverable: QA seed v0 (30-50 câu)

  3. Unit test ingestion output

    • Viết test kiểm tra page/section mapping của A có đúng không (so với file gốc)
    Testing
    Deliverable: Test suite cho ingestion

  4. Script đo recall@k theo chunk size

    • Viết script đo recall@k trên QA seed cho từng chunk size (256/512/1024) mà B đã build
    • Báo cáo kết quả để cả nhóm chọn chunk size mặc định
    Python
    Deliverable: Bảng recall@k theo chunk size

  5. Unit test tokenizer + script EM/F1 sơ bộ

    • Viết unit test: cùng input phải ra cùng token ở pipeline index và pipeline query (bắt lỗi lệch tokenizer sớm)
    • Viết script đo EM/F1 sơ bộ cho S1 trên QA seed
    TestingMetrics
    Deliverable: Tokenizer test pass + EM/F1 sơ bộ cho S1

  6. Benchmark early signal S0-S3

    • Chạy benchmark sơ bộ 4 hệ thống trên QA seed (30-50 câu) để có tín hiệu sớm trước khi đầu tư tiếp vào S4
    Pilot benchmark
    Deliverable: Bảng early signal S0 vs S1 vs S2 vs S3

  7. Implement NLI faithfulness scorer

    • Bắt đầu code module NLI entailment check: tách claim từ câu trả lời, so với context để phân loại entailment/contradiction/neutral
    mDeBERTa-NLI
    Deliverable: Faithfulness scorer v0

  8. Hoàn thiện evaluation set + đo đồng thuận

    • Mở rộng QA seed lên 280-320 câu, đảm bảo tối thiểu 45 câu/loại query
    • Cross-review 20% mẫu, tính Cohen's Kappa với người tạo gốc
    Annotation QA
    Deliverable: Evaluation set final + báo cáo Kappa

  9. Tính toàn bộ metrics + ablation

    • Chạy EM/F1, RAGAS, faithfulness, citation correctness cho cả 5 baseline trên kết quả full benchmark (từ B, C)
    • Tính bootstrap confidence interval (1000 resample) cho từng so sánh
    • Chạy ablation study: tắt từng thành phần để đo đóng góp riêng lẻ
    RAGASBootstrap CI
    Deliverable: Evaluation report v1 đầy đủ

  10. Tổng hợp error taxonomy

    • Gộp báo cáo lỗi từ A, B, C thành 1 taxonomy thống nhất
    • Thống kê tần suất từng loại lỗi theo model/query type, vẽ biểu đồ phân bố
    Matplotlib/Seaborn
    Deliverable: Error taxonomy + biểu đồ

  11. Xây dashboard UI

    • Xây giao diện hiển thị kết quả/biểu đồ metrics cho demo (bảng so sánh baseline, biểu đồ lỗi)
    Streamlit
    Deliverable: Dashboard tích hợp vào demo

  12. Hoàn thiện bảng/biểu đồ kết quả cuối

    • Chuẩn hoá toàn bộ bảng/biểu đồ dùng cho report và slide cuối cùng
    Finalization
    Deliverable: Bộ bảng/biểu đồ final cho report + slide

E — Research/PM/QA

RQ, experiment protocol, report, integration testing
Sứ mệnh: Giữ cả nhóm đi đúng hướng nghiên cứu, đảm bảo chất lượng annotation, và chịu trách nhiệm sản phẩm cuối (report + demo).

  1. Hoàn thiện đề cương & setup hạ tầng làm việc

    • Nộp đề cương xin duyệt, chốt RQ và giả thuyết cùng cả nhóm
    • Setup GitHub repo (cấu trúc thư mục, coding convention), task board
    GitHub
    Deliverable: Approved proposal + repo/task board sẵn sàng

  2. Review corpus & QA seed đầu tiên

    • Kiểm tra corpus A thu thập có đủ đa dạng không, góp ý bổ sung
    • Review 30-50 câu QA seed từ D, sửa câu mơ hồ trước khi dùng làm test v0
    Review

  3. Review ingestion & cập nhật risk log

    • Review code ingestion của A, kiểm tra output có đúng kỳ vọng không
    • Cập nhật risk log (rủi ro parsing, OCR) với dấu hiệu sớm cần theo dõi
    Risk management

  4. Review chunk quality & chốt cấu hình

    • Đọc mẫu chunk thủ công, đánh giá có đủ ngữ cảnh không
    • Dựa trên số liệu recall@k của D, chốt chunk size mặc định cho MVP
    Decision

  5. Review S1 pilot & họp mid-sprint

    • Xem kết quả S1 end-to-end đầu tiên, đối chiếu với kỳ vọng RQ1
    • Tổ chức họp mid-sprint điều chỉnh phân công nếu có thành viên trễ tiến độ
    Sync

  6. Điều phối demo nội bộ đầu tiên

    • Tổ chức buổi demo nội bộ cho MVP end-to-end (S0-S3), ghi nhận vấn đề phát sinh từ góc nhìn người dùng
    Demo

  7. Quyết định trade-off reranker

    • Dựa trên số liệu latency của B, quyết định threshold candidate K cân bằng quality/latency
    Decision

  8. Điều phối annotation & đảm bảo Kappa

    • Giám sát quá trình cross-review evaluation set của D
    • Nếu Cohen's Kappa < 0.6: tổ chức thảo luận thống nhất tiêu chí gán nhãn, phân xử các trường hợp bất đồng còn lại
    Quality control
    Deliverable: Xác nhận Kappa ≥0.6 trước khi cho phép freeze config

  9. Giám sát ngân sách & tổng hợp kết quả

    • Theo dõi chi phí API thực tế so với cap đã định (mục 18 Proposal v2) trong tuần chạy full benchmark
    • Tổng hợp kết quả sơ bộ từ B, C, D thành bản nháp đầu tiên
    Budget monitoring

  10. Viết báo cáo phân tích lỗi

    • Tổng hợp error taxonomy từ D thành văn bản mạch lạc — input trực tiếp cho chương Results/Discussion
    Writing
    Deliverable: Draft chương Error Analysis

  11. Viết Chương 1-4 báo cáo + outline slide

    • Viết Introduction, Related Work, Dataset, Methodology (phần không phụ thuộc kết quả cuối)
    • Lên outline slide trình bày
    Overleaf/LaTeX
    Deliverable: Draft Chương 1-4 + outline slide

  12. Hoàn thiện report, slide, demo & rehearsal

    • Ghép toàn bộ chương còn lại (Results, Discussion, Conclusion) với số liệu final từ D
    • Hoàn thiện slide, viết script demo, tổ chức rehearsal toàn nhóm ít nhất 1 lần
    Finalization
    Deliverable: Report + slide + demo script hoàn chỉnh
Mỗi thành viên có thể dùng riêng phần của mình làm checklist cá nhân — vẫn cần đối chiếu với bảng tổng theo tuần để không lệch tiến độ giữa các role phụ thuộc lẫn nhau (vd: C phụ thuộc output của B, D phụ thuộc output của cả B và C).
